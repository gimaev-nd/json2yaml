# AGENTS.md — инструкции для ИИ-агентов

## О проекте

**json2yaml.ru** — веб-приложение «редактор-конвертер» JSON ⇄ YAML. Два редактора
Monaco на одной странице; правки в одном автоматически (с debounce) конвертируются
и подставляются в другой через API.

Язык проекта (код, комментарии, коммиты, ответы агента) — **русский**.

## Стек

- **Бэкенд:** Python ≥ 3.13, Litestar 2.x, ruyaml, uvicorn. Шаблонизатора нет:
  `index.html` — обычная статика, отдаётся как файл.
- **Фронтенд:** vanilla JS, Monaco Editor, Tailwind (browser-сборка) — всё лежит
  локально в `src/static/vendor/`, сборки и npm нет.
- **Пакетный менеджер:** uv (`pyproject.toml` + `uv.lock`). pip/poetry не используем.

## Структура

- `src/backends/<имя>/` — бекенды (пока один: `litestar`). У каждого свои
  `app.py` (точка входа: роуты, отдача `index.html` и статики) и `helpers.py`
  (утилиты конвертации `as_yaml`, `as_pretty_json`, `get_error`). Путь к общей
  статике вычисляется от `__file__`, поэтому бекенд можно запускать из любого
  каталога.
- `src/static/site/` — статичная страница `index.html` и примеры `example.json/yaml`
  (фронт подгружает их fetch'ем при старте).
- `src/static/js/app.js` — логика редакторов и синхронизации через API.
- `src/static/vendor/` — сторонние библиотеки, закоммичены в репозиторий.
  **Не редактировать и не форматировать.**

## Команды

```bash
make install    # установка зависимостей (uv sync)
make run        # запуск dev-сервера (по умолчанию бекенд litestar;
                # другой бекенд: make run BACKEND=<имя>)
make lint       # линт index.html (djlint, dev-зависимость)
make test       # контрактные тесты: поднимает litestar-бекенд на порту
                # TEST_PORT (по умолчанию 8010), прогоняет hurl-файлы
                # из tests/hurls и останавливает бекенд
```

Без make: `cd src/backends/litestar && uv run uvicorn app:app --reload`.
Пути к статике в `app.py` вычисляются от `__file__`, поэтому каталог запуска
не важен. Контрактные тесты — на hurl (`tests/hurls/`), они ходят только по
HTTP и не зависят от реализации бекенда; нужен установленный бинарь `hurl`.

## API (контракт, менять согласованно с фронтом)

- `POST /api/json-to-yaml` и `POST /api/yaml-to-json`
- Тело: JSON `{"text": "<исходный текст>"}` (см. `Text` в `app.py` бекенда).
- Успех: `200`, тело — результат конвертации как plain text.
- Ошибка парсинга: `422`, тело — JSON единого вида для обоих направлений:
  `{"message": "<текст для человека>", "line": 3, "column": 7}`. `line`/`column`
  нумеруются с единицы; `null` — если позиция в исходном тексте неизвестна
  (например, `!!int abc` падает `ValueError` без метки). Фронт показывает
  `message` в закрываемой панели вместо результата и подсвечивает строку
  в редакторе с ошибкой.

## Соглашения по коду

- Конвертация YAML — только через `ruyaml` (safe-трюк на чтение, кастомный дампер
  с отступом 2 в `helpers.py` бекенда); `pyyaml` не добавлять.
- JSON всегда сериализуем с `ensure_ascii=False` — кириллица не должна уезжать
  в `\uXXXX`.
- Хендлеры синхронные с `sync_to_thread=False` — не добавлять в них блокирующий
  ввод-вывод.
- Любая ошибка разбора входного текста — это `422` с телом `get_error(...)`,
  никогда не `500`. В `y2j` недостаточно ловить `ScannerError`/`ParserError`:
  ruyaml отдаёт наружу и `DuplicateKeyError`, и `ComposerError`, а на `!!int abc`
  вообще летит обычный `ValueError`. Поэтому ловим `YAMLError` плюс общий
  `Exception` (как в `j2y`); регрессы закреплены в `tests/hurls/05-*.hurl`.
- `get_error` — единственное место, где формируется описание ошибки: он отдаёт
  `{"message", "line", "column"}` и переводит технические сообщения `json`/`ruyaml`
  на русский (`JSON_MESSAGES`, `YAML_PATTERNS`). Не отдавать наружу `vars(exp)`:
  это сырой вывод для разработчика, а не текст для человека.
- Ошибку 422 отдавать через `error_response(...)` в `app.py`: успешный ответ —
  `text/plain`, и без явного `media_type="application/json"` Litestar пытается
  сериализовать dict как plain text и падает в 500.
- Зависимости добавлять только через `uv add` (dev — `uv add --dev`).
- Коммиты: короткое сообщение на русском в повелительном наклонении, как в истории
  («Фронт: получение данных с бека», «API конвертации»).
- В `index.html` Tailwind-классы форматируются djlint — перед коммитом прогонять
  `djlint --reformat` при правках страницы.
